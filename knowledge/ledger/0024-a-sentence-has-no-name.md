# 0024 — a sentence has no name

## What changed

**The store says what may have a URN, and says it in two rules instead of one.**
`knowledge/NAMING.md` is at `0.3.0`. It made two claims and they were read as
one for eight iterations: *subjects are URNs* is a naming rule about what may be
named, and *the file layout mirrors the URN* is a storage rule about where a
named thing lives. Nothing separated them, so "anything addressable is a
subject" was read as "anything addressable should have a file under
`subjects/`", and three unrelated questions looked like one. They are now two
labelled sections and each rule says which it is.

**The criterion that decides all three, stated for the first time.** A URN names
a thing whose identity is a pure function of its own properties, never of its
position in a document or an insertion order. This is not new behaviour — it is
what the alias builder has done since `0002`, whose own comment says the former
id could be computed *"because the old id was a pure function of fields the new
record still carries"*. It had never been written as a rule, so it could not be
applied to a case it had not already met.

**`0004-t1`: yes. Patterns are subjects, under a `pattern:` namespace.** Six
records under `subjects/pattern/`, generated by `Update-KnowledgePatternSubject`
from the pattern log and wired into the `Knowledge` build task. A pattern's id
is its iteration plus its authored slug: intrinsic, not positional, stable
across regeneration. The corroboration is that
`corpus/docker/init/01-schema.sql` reached the identical identifier without
being told — `pattern.pattern_id` is the one `TEXT PRIMARY KEY` in a schema
where every other body took a `BIGSERIAL`.

**`0007-t2` and `0008`: no, and the reasons are recorded rather than the
verdicts.** A claim's only natural key is *(iteration, section, ordinal)*, and
the ordinal is a position in prose that is re-parsed on every ingest: edit a
sentence into an earlier entry and `claim:0007/3` names a different sentence. A
measurement is a reading about a thing at a time rather than a thing; giving one
a URN mints a subject every time the number moves, and under *removal is not an
operation this store has* the population would grow with the build count
forever. Both reasons are in `NAMING.md`, because the fourth instance of this
shape is resolved by a reason and not by a verdict.

**Patterns are subjects and `facet-health` does not grade them.**
`docs/constraints.md`, with the measurement that lifts it. Answering `0004-t1`
yes does not remove the objection it was declined under — that classifying a
population in the turn that creates it is what reflection discipline exists to
prevent — it moves it, and `0003-t1` already records `facet-health` grading
itself flatteringly.

**The corpus ingester no longer decides what an example is worth.** The inline
map that stamped `1.0`, `3.0`, `4.0` and `2.5` is gone.
`corpus/sampling/weights.json` holds them, versioned and dated, with the
population size behind each number recorded next to it — two rows, for the
weight of four. `Export-CorpusTrainingSet` emits no weight unless
`-WeightProfile` is passed, and `Export-CorpusSql` omits the column entirely
when none was decided so the schema default stands.

**The recurrence finder was pointed at transcript episodes.** Measurement only;
nothing in the finder changed.

**A constraint on publishing the corpus**, in `docs/constraints.md`, with the
condition that lifts it.

## What I learned

**The heredoc trap scores Lift 7, not zero, and that is the more interesting
answer the other way round.** `Measure-CorpusRecurrence`'s own docstring says
the trap *"reaches fewer than two claim sections, so it scores nothing here"*
and calls that the argument for ingesting transcripts. Run against transcript
episodes — foreground being an episode that contained a failed tool call,
background every other episode, the same subtraction the ledger version does —
`heredoc` returns **Lift 7, 7 laps, 13 occurrences, background 0, rank 98 of
1,121 terms**. Its top example is *"The heredoc is choking on the embedded shell
metacharacters"*: the trap firing, not a discussion of it.

So the finder was never blind to this class. It was pointed at a population that
does not record incidents. That is a smaller and better claim than the one that
was about to be written, and it could only be told apart by running it.

**The corpus cannot see a failed tool call at all.** `Import-CorpusTranscript`
sets `IsError` and `ResultChars` to `$null` unconditionally, for all 1,357 tool
calls across three sessions, while the raw transcripts carry 74 `is_error`
results. The schema comment says tool results are *measured, never stored*; the
measuring half was never written. The foreground for the run above had to be
recovered by re-parsing the JSONL outside the module.

**A redactor's model is the machine it was written on.** Run over 517 files of
eight published modules, `Protect-CorpusText` caught what it claims to — 28
`<home>`, 57 `<email>`, including a developer's home directory inside a Pester
stack trace — and missed 284 absolute paths outside the user directory, 355
`github.com` account URLs, 107 IP addresses, 44 network shares, 39 GUIDs and 22
manifest author fields carrying eight real human and company names. Not one of
those is a weakness in a rule. Every rule it has is a fact about the person
running it — their home directory, their account names, their repository root —
and none of them can see a third party, because there is no list of third
parties and there cannot be one.

**A gate that compares whole trees fails loudly when a second producer appears,
and that is it working.** The freshness test reported all six pattern subjects
as *no longer generated* the moment they were written, because its fresh
regeneration ran one producer and the store now has two. The fix was to teach it
the second producer, not to narrow the comparison.

## What I could not verify

**That excluding `pattern:` from facet-health is the right call rather than the
convenient one.** The exclusion is recorded as a constraint with a condition,
and the condition is a measurement nobody has run. I did not run it in this pass
because running it would have meant writing the assignments whose absence is the
exclusion.

**That the exclusion holds by anything other than accident.** It is structural,
not enforced: a facet's eligible population is inferred from the namespaces it
has assigned into, so a namespace with no assignments is invisible. I verified
this empirically — six subjects added, eligible population moved 93 to 94, and
the plus one is the new public function — but nothing prevents the first
assignment written against a `pattern:` subject from silently making all six
eligible. I wrote that down instead of gating it, and a written-down invariant
is the weakest kind.

**That the transcript foreground/background split measures what the ledger
version measures.** The ledger's foreground is where an author *recorded*
trouble; mine is where a tool *returned* an error. Those correlate and are not
the same thing, and 47 episodes across 3 sessions is a small population — 24
foreground against 23 background. I did not test whether a different episode
boundary or a different error signal moves `heredoc` off rank 98.

**That the heredoc mentions are all the trap and none of them discussion.** I
read three of the seven episodes and all three were the trap firing. I did not
read the other four, and this corpus is written by someone who also writes
*about* the trap, which is the contamination the measurement is least able to
see.

**That the redaction sweep says anything about the corpus as it is actually
built.** `gallery/modules/` is not ingested. The exposure is transcripts quoting
whatever was on screen, and I did not measure how much of those eight modules
reached a transcript. The sweep tested the redactor against unseen input, which
is what it was for, and it is not clearance.

**That 517 files of PowerShell is a representative adversary.** All eight
modules are from one ecosystem and one gallery. A corpus built from a repository
carrying Terraform state, an environment file, or a notebook would present
classes of secret none of my probes looked for.

## Dimensional impact

Five questions, under the evidence rule.

**1. Did this reveal a dimension that does not exist yet?** **Yes, and it is the
one that was withdrawn.** `namespace` was declined in `0002` on the explicit
ground that every subject was `psmodule:` — *"It returns when a second namespace
does. A dimension with one value is not a dimension."* `pattern:` is a second
namespace, so the condition is met. **Reinstated as a proposal in
`docs/improvements.md`, not taken:** the same rule that withdrew it forbids
taking it in the pass that qualified it. Noted there and worth repeating: a
`namespace` facet assigning into `pattern:` would lift the facet-health
exclusion as a side effect rather than as a decision.

**2. Is an existing facet doing two jobs?** No.

**3. Did two facets turn out to be the same thing?** No.

**4. Did anything classify at a depth the facet did not anticipate?** Not
applicable; no assignment was written this pass outside the generated ones.

**5. Could this facet classify facets?** Worth recording rather than answered:
`facet:` and `pattern:` are now both namespaces holding things this project
produced about itself, and `facet-health` grades one and is forbidden the other.
Whether that asymmetry is principled or historical is `0024-t1`.

3. **[0024-t3] Every hashtable in this corpus is one English word from the same
   collapse.** `$seen.Values` returned the row for the word *"values"* and
   turned 800 rows into 1, silently — PowerShell resolves a hashtable key as a
   property before the real member, and this corpus is keyed by English prose
   throughout. It was found by arithmetic rather than by review, and nothing
   says it was the only one. `Measure-CorpusRecurrence` now calls `get_Keys()`
   at every site and its test plants three colliding names, but the language has
   more than three: `count`, `keys`, `values`, `length`, `item` and `remove` are
   all ordinary words in this vocabulary. Naming three in a test is not a bound
   on the defect. `knowledge/patterns/0023` is the general shape.
