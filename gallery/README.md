# gallery — real modules, parsed and recorded

The parser had seen a nine-node fixture and this repository. This is the input
that is neither: modules written by other people, pinned by version, chosen
because each breaks something different.

```powershell
./gallery/fetch.ps1        # download and verify against the lock
./build.ps1 -Task Build    # the parser under test
./gallery/run.ps1          # one result file per module under results/
```

## What is here

| Path | What it is |
| --- | --- |
| `corpus.json` | the pinned module list. Each entry names **what it stresses** and **what was predicted**, written before the first run. |
| `corpus.lock.json` | the bytes: source URI and SHA-256 per package. Generated by `fetch.ps1 -UpdateLock`. |
| `contract/run-result.schema.json` | the result shape. Additive changes bump minor; shape changes bump major. |
| `results/` | one JSON file per module per run, committed. Git is the history — there is no database. |
| `modules/` | the vendored sources. **Not committed**, and `.gitignore` says so. |

## Three rules

**The source is never committed.** A corpus has to be reproducible without being
a redistribution, so what is committed is a URL, a version and a hash.
`fetch.ps1` refuses to run against an unpinned module and refuses bytes that do
not match the lock.

**A run that throws still produces a record.** Failure, timeout and
never-vendored all write a result file with the failure in it. A corpus where
failures are absent measures only the modules that worked, and the modules that
worked are not the interesting ones.

**Nothing here imports a corpus module.** `run.ps1` points PSModuleGraph at a
directory and PSModuleGraph reads it. The core constraint in `CLAUDE.md` is
under more pressure here than anywhere else in the repository, because these are
modules nobody vetted — which is exactly the situation a user is in. If
something in this directory would be easier with an import, that is the bug.

## Reading a result

Two numbers next to each other, not one: `counts.nodes` against
`counts.declaredExports`. A module that declares seventy exports and yields four
nodes has not been understood, whatever the outcome field says. A module that
declares none and yields none may be perfectly described. Nothing else in the
record can tell those apart.

`gallery/modules/` and `corpus/` are unrelated. `corpus/` mines this
repository's own development record; this directory holds other people's code.
